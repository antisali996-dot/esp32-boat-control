## 1. 本轮改动

### 1.1 诊断证据（可区分软件停机 / 主控重启 / 无线失联）

启动时输出一次：

```
BOOT FW=JAYFWB4-...
BOOT VER=20261103-590rpm-r4 ROLE=BOAT MAC=.. RESET=POWERON(1)
BOOT TARGET_RPM=590 OVERSPEED_RPM=600 STEER_DEG=20 ANGLE=70..110 PULSE=1278..1722us
```

`RESET=` 取自 `esp_reset_reason()`，能直接区分主控是否重新启动：
`POWERON` / `SOFTWARE` / `PANIC` / `TASK_WDT` / `BROWNOUT` 等。

运行中每秒输出两行（一行放不下，拆成两行）：

```
RUN up=123s rpm=588.4 pulses=71 target=590 pwm=142 integral=88.3 maxgap=52ms
RUN fault=NONE rx=4012 bad=3 lastrx=124ms age=124ms servo=1500us
```

- `up` = 上电以来秒数。**如果停机前后 `up` 归零，就是主控重新启动，不是软件保护。**
- `maxgap` = 本次上电以来控制周期的最大间隔，用来判断显示/通讯是否曾拖慢控制。
- `lastrx` / `age` 用来区分“无线失联”和其它停机。

状态变化单独输出一次，不每轮刷屏：

```
EVENT LINK=LOST count=4012
EVENT MOTOR_FAULT=OVERSPEED rpm=612.0 pwm=141 pulses=76 interval=51ms target=590 threshold=600
EVENT MOTOR_FAULT=NO_ENCODER_PULSES
EVENT MOTOR_FAULT=SUSTAINED_LOW_SPEED
EVENT DISPLAY=DISABLED (control continues)
EVENT DISPLAY_ERROR=2 (control continues)
```

### 1.2 屏幕不再阻塞控制

- 主循环只做：电机控制、舵机目标更新、无线状态处理、收包与非阻塞推送显示快照。
- 新建低优先级任务 `display`（优先级 1，与 `loopTask` 相同，但固定在 core 0；
  `loopTask` 在 core 1），**所有 `Wire` 与 `U8g2` 访问只在这个任务里**。
- 用长度 1 的队列传 `DisplaySnapshot`，主循环用 `xQueueOverwrite` 非阻塞覆盖写入。
  队列满时覆盖旧值，主循环从不等待。
- 屏幕初始化、探测（0x3C/0x3D）、10 秒重发初始化、掉线恢复全部在显示任务内。
- 队列或任务创建失败 → `displayEnabled=false`，打印一次 `DISPLAY TASK CREATE FAILED`，
  控制逻辑继续跑。`publishDisplay()` 在禁用时直接返回。
- 主循环里没有任何 `initDisplay` / `sendBuffer` / `Wire` 调用（已用脚本核查，见 §3）。

### 1.3 590 目标 + 600 超速锁存

- 目标统一为 `FW_TARGET_RPM = 590`，生效路径里已无 580。
- 新增故障类型 `MotorControl::OVERSPEED`。
- 有效测速 `rpm >= 600` 时，**在本次更新内立刻**把 `pwm` 置 0、积分清零、锁存故障。
  超速判断放在无脉冲/低速判断之前，且不复用低速跟踪状态。
- 锁存后 `fault != NONE` 直接返回，任何转速输入都不会重启动力。只有重新上电才清除。
- 触发瞬间记录并只打印一次：`rpm`、`pwm`、本周期脉冲数、控制间隔、目标、阈值。
- 抗积分饱和改为跟随**真正下发的输出**：输出被启动斜率（每周期最多 +10）或上限 255
  卡住时，积分不再继续积累推动加速的分量。
- 未增加任何电气制动。

> **“达到 600 才关闭 PWM”不是物理转速绝不超 600 的保证。**
> 惯量、采样延迟和测速误差都会让实际峰值高于触发点。必要的提前限速裕量
> 必须由上位机根据实测数据另行确定。本轮未做该裕量，也未声称做到。

### 1.4 舵机

- `setTimerWidth(14)` 在 `attach()` **之前**显式调用（14 位、50Hz → 约 1.22us/tick）。
- 仍为 50Hz、中位 1500us、左右各 20°（1278～1722us）。
- 电机用 LEDC 通道 2（映射到 timer 1），舵机库分配 timer 0，两者不同定时器。
- 只有最终目标脉宽变化才写舵机；`ServoOutput.lastPulseUs` 初值 -1，**首次回中一定输出**。
- 未改摇杆死区（1750/2150）与端点映射，等实测数据。
- 没有用 `detach()` 或停发脉冲来掩盖抖动。

### 1.5 遥控发送状态机

状态：`INIT → READY → WAIT_DONE →(超时)→ BACKOFF → REBUILD → READY`，连续 3 次重建失败 → `FAULT`。

- 同一时刻只允许一个在途发送（`canSend()` 要求 `pendingToken == 0`）。
- 三类失败分别计数：`localSendErrors`、`sendFailCallbacks`、`callbackTimeouts`。
- 普通“对端未收到”只计数，**不重启无线**。
- 回调超时：先在临界区内清 `pendingToken` 并离开可发送状态，**然后**才退避重建。
- 退避固定 500 / 1000 / 2000 ms；连续 3 次重建失败进入 `FAULT` 并打印，不再快速重试。
- 回调只写 `pendingCallback` / `callbackToken`，由主循环搬运；不在回调里推动恢复流程。
- 迟到回调：回调携带令牌，只有与 `inFlightToken` 相同才被接受；
  本地发送错误也会立刻吊销令牌，避免把随后到达的迟到回调算作本次结果。

**关于迟到回调的证据边界（重要）**

对本地 `libespnow.a` 反汇编核实（`espnow.o` / `manatick.o`，xtensa-esp32-elf-objdump）：

- `mt_unregister_send_cb()` 执行 `s32i.n a9, a8, 56`（a9=0）——把回调指针清零；
- `mt_deinit()` 在入口同样执行 `s32i a3, a2, 56`——清零回调指针；
- `mt_send_cb` 在调用前重新 `l32i.n a3, a2, 56` 并判空后 `callx8`。

即：注销之后再触发的回调不会进入应用代码。

**但仍有一个无法仅靠静态证据排除的窗口**：`esp_now_deinit()` 不等待已经进入核心、
尚未返回的在途发送。如果某个回调在注销前已越过空指针判断，它仍可能在重建后落地。
本实现用令牌丢弃它（不会错误结束新一轮发送），但这属于“设计上已处理”，
不是“已实测证明”。已在重建成功后加 100ms 静默窗口把窗口压小，同样不是证明。

**这一项按需求记为：机械隔离已实现且可解释，彻底验证待实机/长跑。**

## 6. 给上位机的最小采集清单

要判断“反复停启”是保护锁存、主控重启还是无线失联，至少需要：

1. **停机前后的完整串口日志**，以及每段开头的 `BOOT RESET=` 行。
2. **停机期间 `RUN up=` 是否归零**：归零 = 主控重新启动；不归零 = 软件保护或无线问题。
3. **舵机端与主控端的供电电压**（同时记录，看是否同时跌落）。
4. **驱动板温升、编码器脉冲数与测速对照**（同一时间段，判断是堵转、过载还是测速丢失）。

补充说明：现有实现里故障是**锁存**的，锁存后不会自动重启动力。
因此“反复停启”在软件层面只能来自两种情况：主控反复复位，或每次都有人/机构重新上电。
**不得把“保护锁存”解释成“软件自动反复启动”** —— 代码里没有这条路径。
